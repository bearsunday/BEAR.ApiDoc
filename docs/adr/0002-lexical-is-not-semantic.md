# ADR 0002: 字句一致は意味同値ではない — 語彙と観測

## Status

Proposed

## Context

ADR 0001 では、パラメータ名とエンティティプロパティからドメインの語彙（オントロジー）を抽出し、ALPS descriptor を生成する構想を示した。`TermUsageIndex` はその第一歩として、API 全体で使われる term（パラメータ名・スキーマプロパティ名）を収集し、同名の ALPS descriptor を重ねて「字句的 ALPS カバレッジ」を算出する。

ここに根本的な但し書きがある。**term の収集は字句（綴り）の一致であって、意味的同値の証明ではない。** 特に `name`, `age`, `status` のような汎用語で問題が顕在化する。

- **同名異義（homonym）**: `Person.age`（年）と `Cache.age`（経過秒）は次元すら違う。`name` が一意識別子の箇所と、ただの表示ラベルの箇所がある。
- **異名同義（synonym）**: `customerName` / `userName` が同一概念のこともある。

汎用語は出現頻度が最も高く（情報検索の stop-word に相当）、識別力が低く、意味は「どこで使われるか」という文脈に外注されている。したがって字句索引のカバレッジは、汎用語において最も楽観的に＝最も不正確に振れる。

語彙が失敗してきた歴史的パターンは一点に収束する。**語彙は、それを使う行為から切り離された瞬間に死ぬ。** 重厚な ontology やデータディクショナリが形骸化したのは、定義（宣言）と実装（使用）の一致を観測し続けるループが切れていたからだ。

## Decision

`TermUsageIndex` は **意味を強制せず、使用を観測する** 側に徹する。

1. **字句一致だと明示する** — 生成物の冒頭に「これは字句識別子の一致であり、意味的同値を証明しない」と必ず記す。カバレッジは達成度ではなく診断シグナルである。
2. **使用箇所を全可視化する** — どの API・どのスキーマで term が出現するかを残す（ボトムアップの実態把握）。
3. **ALPS を重ねるが融合しない** — 同名 descriptor があれば併記するが、それを「同一概念の証明」とは扱わない。
4. **判断は人間に委ねる** — 「`name` が N 箇所で使われている。これは 1 概念か N 概念か？」という問いを提示する。同義なら 1 つの descriptor を参照（真の再利用）、異義なら名前を特化するか、親 descriptor によって文脈へ意味を逃がす。

リンク（ALPS `href` / 命名）は意味の **主張** であって **保証** ではない。貼って終わりではなく、宣言と観測の一致を回し続けて初めて語彙は生きる。

## Consequences

### Positive

- 索引はソースから毎回導出されるため、宣言と実態が原理的に乖離しない。人間が「正」を二重管理する隙間がない。
- カバレッジが「逸脱監視の基準線」になる。`testMarkdownIsDeterministic`（生成物を fixture に固定し差分で落とす）は、語彙の使われ方の逸脱を検知するスナップショットテストとして既に機能している。
- 字句レベルでも有用な逸脱を捕捉できる。同名 term の形（型 / format）の乖離、ALPS カバレッジの低下、孤児 term、synonym の急増など。

### Negative / Risks

- カバレッジ指標を「意味的網羅」と誤読される恐れ → 冒頭の降参宣言で緩和する。
- 逸脱監視は「正当な進化」と「退行」を区別できないとノイズになる → 基準線（fixture / snapshot）は、意図した変更時に人間が更新する運用とセットにする。
- 汎用語の真の診断には「形の比較」まで踏み込む必要がある（将来課題）。同名 term の型・format を突き合わせ、同形（同義の蓋然性）と異形（homonym の蓋然性）を分離する。
